# 과업 성공 중심 하네스 v4.0

목표는 **합의한 과업을 실제 근거로 완료**하는 것이다. 역할은 전문 기능, 모델은 교체 가능한 실행자다. 역할 수·문서 수·호출 수를 성과로 삼지 않는다.

## 시작과 메인 세션

메인은 이 문서 → [공통 원칙](core/principles.md) → 현재 과업을 읽는다. 목표·성공 기준을 유지하고 필요한 작업만 배분하며 결과를 통합한다. 별도 관리자 에이전트를 추가하지 않는다. 명확한 작은 작업은 직접 수행·검증한다.

모델 연결은 [모델 운영표](core/models.md)에서 확인한다. 기본은 `DEFAULT`, 탐색은 `FAST`, 중요한 난제는 조건부 `DEEP`다. **최초 연결·모델/플랫폼 변경 때** [실행 연결](adapters/runtime.md)을 확인하고 실제 모델·도구·권한을 점검한다. 유효한 동일 설정은 반복 조사하지 않는다.

| 필요한 기여 | 필요한 때만 읽을 역할 |
| --- | --- |
| 관련 코드·자료의 위치와 구조 | [explorer](roles/explorer.md) |
| 구현 전 접근법·대안·검증 설계 | [planner](roles/planner.md) |
| 범위가 정해진 변경 | [patcher](roles/patcher.md) |
| 계획·변경의 구체적 결함 검토 | [reviewer](roles/reviewer.md) |
| 테스트·실험·실패 진단 | [tester](roles/tester.md) |

위임·병렬 작업·중요 실험에는 [운영 절차](core/workflow.md)를 적용한다. 모든 역할을 순서대로 호출하지 않는다. 전문 세션에는 공통 원칙 + 자기 역할 + 작업 패킷만 전달한다. 실제 모델은 패킷으로 전달하고 모델표를 모두 재주입하지 않는다.

## 기록과 지식

짧은 질의는 대화로 끝낸다. 기록이 필요한 새 과업은 [task.md](tasks/_template/task.md) 하나를 복사한다. 기존 과업의 파일 체계는 유지한다. 이미 읽고 현재 맥락에 남은 유효 지침은 다시 읽지 않는다.

기존 지식이 필요하면 [Wiki 인덱스](../wiki/index.md)에서 관련 페이지만 확인한다. 실제 Wiki 편집자만 [지식 운영](playbooks/llm-wiki.md)을 읽는다. 원문·조사 기록·전환 안내는 기본 입력이 아니다.

## 첫 입력

```text
references/이정민/harness/README.md를 진입점으로 메인 세션을 운영하라.
과업: [실제 요청]
현재 기록: [과업 경로 또는 대화]
실행 프로필: [core/models.md의 선택값; 기본 openai-balanced]
허용 경로·명령·자원·외부 제공자·Wiki 범위: [실제 조건]
필요한 역할만 사용하고, 실제 모델/권한이 확인되지 않으면 추정하지 마라.
성공 기준을 검증하고 미실행·한계를 구분해 보고하라.
```

이 묶음은 Markdown 운영 지침이다. 자동 모델 전환·에이전트 등록·권한 강제 기능은 없다. 설치기·루트/전역 설정 변경도 없다. [참고 사례](reference/cases.md), [파일 전환·검사](REFACTOR.md), [실운영 비교 계획](EVALUATION.md)은 해당 작업 때만 읽는다.
