# v3.0 통합 재구성 — 적용과 검증

작성일: 2026-09-20. 이 대화의 과업 성공 중심 v1 → v2 → v2.1을 재구성한 버전이다. 과거 다른 대화의 Sol 중심 V3와 다른 계열이다. 실제 모델·WSL·사용자 저장소에 적용하지 않았다.

## 1. 변경의 핵심

공통 판단은 `core/principles.md`, 역할별 차이는 `roles/`, 위임·고영향·기록 확장은 `core/workflow.md`에 둔다. Wiki 작성과 형식은 `playbooks/llm-wiki.md` 한곳으로 모았다. 원문·형식 설명·이력은 기본 입력에서 제외한다.

새 과업은 한 문서로 시작하되 계획·근거가 커지면 필요한 절만 분리한다. Wiki 반영은 새로 재사용할 지식이 있는 경우만 수행한다. 근거와 권한을 줄인 것이 아니라 읽기 경로와 중복 기록을 줄인 설계다. 품질 보존은 규칙 검토와 실제 모델 평가를 구분한다.

## 2. 새 구조

```text
references/이정민/
├── harness/
│   ├── README.md
│   ├── REFACTOR.md
│   ├── core/{principles,workflow}.md
│   ├── roles/{astra,sol,terra,luna}.md
│   ├── playbooks/llm-wiki.md
│   ├── templates/wiki-page.md
│   └── tasks/_template/task.md
├── raw/
│   ├── README.md
│   └── karpathy/{llm-wiki,SOURCE}.md
└── wiki/
    ├── index.md
    ├── log.md
    ├── sources/{karpathy-llm-wiki,google-open-knowledge-format}.md
    ├── decisions/harness-wiki-integration.md
    ├── concepts/
    ├── systems/
    ├── research/{papers,datasets,benchmarks}/
    └── lessons/
```

빈 주제 폴더는 실제 지식이 생길 때만 사용한다. 모델·코드·로그는 승인된 기존 프로젝트 경로에 둔다.

## 3. 기본 실행과 조건별 확장

| 상황 | 읽기·기록 |
| --- | --- |
| 단순 질의 | README·공통 원칙·자기 역할 + 대화. 과업 파일 없음 |
| 새 기록 과업 | 위 지침 + `tasks/<과업명>/task.md` 한 개 |
| 기존 과업 재개 | 위 지침 + 기존 `brief.md`·`state.md`, 필요한 원본만 |
| 위임/병렬/고비용/고영향/분리 | `core/workflow.md`를 추가 |
| 전문 역할 새 세션 | 공통 원칙 + 자기 역할 + 작업 패킷. 누락 맥락만 과업에서 확인 |
| 지식 조회 | 인덱스 + 관련 지식/필요 원자료. 이미 전달됐으면 검색 생략 |
| Wiki 작성 | 편집자만 `playbooks/llm-wiki.md`. 새 페이지일 때 템플릿 추가 |
| 정정/외부 교환 | 영향받은 주장·링크·외부 의존과 공식 사양을 필요한 만큼 확인 |

이것은 자동 문서 로더가 아니다. 실행자가 경로를 전달해야 한다. 역할의 실제 모델·세션·전달 방식은 과업에 기록하며 추정 ID를 채우지 않는다. 같은 세션에서 역할을 바꾸는 것은 독립 검토가 아니다.

## 4. v2.1에서 적용 — 일괄 덮어쓰지 않기

별도 폴더에 압축을 풀고 기존 저장소와 비교한다. 기존 과업·Wiki·로그·원자료·개인 수정은 먼저 보존한다. 이 묶음은 자동 설치·삭제·마이그레이션을 하지 않는다.

| 이전 경로 | v3에서의 처리 |
| --- | --- |
| `harness/README.md`, `core/`, `roles/` | 새 공통 기준을 확인하고 개인 변경을 비교 병합 |
| `harness/tasks/_template/{brief,plan,state,evidence,result}.md` | 새 과업은 `task.md` 사용. 기존 실제 과업은 유지 |
| `wiki/schema.md` + `harness/playbooks/llm-wiki.md` | 후자 하나를 현재 규약으로 사용 |
| `wiki/_templates/page.md` | `harness/templates/wiki-page.md`로 이동한 새 틀 사용 |
| `harness/V2_NOTES.md`, `harness/OKF_NOTES.md` | 이전 ZIP의 제작 이력. 현재 규칙으로 불러오지 않음 |
| `raw/karpathy/llm-wiki.md` | 동일 본문. 다시 내려받거나 변환하지 않음 |
| `raw/karpathy/SOURCE.md` | 출처·이전 한계 유지, 안내 링크와 v3 보존 범위만 갱신 |
| `wiki/index.md`, `wiki/log.md`, 기존 내용 페이지 | 사용자 기록을 덮어쓰지 말고 필요한 항목만 병합 |

기존 파일에서 `wiki/schema.md`, `_templates/page.md`, 두 과거 NOTES를 참조하는지 검색하여 새 경로 또는 보존 이력으로 연결한다. 역참조가 남았으면 이전 파일을 삭제하지 않는다. 필요할 때만 안내용 문서로 남기되 두 규약을 동시에 적용하지 않는다. 이 패키지는 알려지지 않은 사용자 파일의 역참조를 검사하지 못했다.

기존 다섯 파일 과업은 진행 중 구조 변경 없이 이어간다. 새 `task.md`를 덧붙여 두 원장을 만들지 않는다. 사용자 Wiki의 유효한 출처·검증·확장 필드는 최소 예시와 다르다는 이유로 제거하지 않는다. 원자료 재배포 조건은 자동으로 달라지지 않는다.

기존 사용자 인덱스·로그를 이번 초기 파일로 교체하지 않는다. v2/v2.1 ZIP에는 원래 제작 기록이 남아 있다. 이번 ZIP을 적용하기 위해 프로젝트 루트·전역 설정·Git 이력을 수정할 필요는 없다. 기존 자동 진입점이 있다면 사용자가 실제 적용 지침을 확인하고 충돌을 조정한다.

## 5. 보존한 품질 기준

| 기준 | 현재 위치 |
| --- | --- |
| 성공 기준·제약·부정 결과·미검증 판정 | 공통 원칙 + Astra + task |
| 원자료·관측/해석·실행 여부·실패 기록 | 공통 원칙 + 역할 반환 + task 근거 |
| 사전 연구 검토·데이터 누수·최종 평가 보호 | 운영 절차 + Sol |
| 독립 검토의 작성 참여·별도 맥락·원본 확인 | 공통 원칙 + 운영 절차 + Sol |
| 최소 수정·부분 보완·무의미한 반복 중단 | 공통 원칙 + 운영 절차 |
| 한 편집자·파일별 담당·충돌 처리 | 공통 원칙 + 지식 운영 |
| 권한·비밀정보·위험 코드·외부 지시 경계 | 공통 원칙 |
| Wiki 출처·조건·정정·이전 검증의 유효 범위 | 지식 운영 |
| 실제 모델/세션과 역할명의 구분 | README + task + 운영 절차 |
| 원문 사본·과거 이력·기존 과업 보존 | raw + Wiki 로그 + 전환 안내 |

이는 문서상 기준 추적표다. 규칙을 적었다고 모델이 반드시 지키는 것은 아니며 자동 권한 통제도 아니다.

## 6. 정적 측정

| 측정 | 초기 v1 | 이전 v2.1 | 통합 v3 | v2.1 대비 |
| --- | ---: | ---: | ---: | ---: |
| Markdown 파일 수 | 12 | 25 | 19 | 24.0% 감소 |
| 전체 문자 수 — 안내·원문 포함 | 28,918 | 82,696 | 37,921 | 54.1% 감소 |
| 기본 Astra 지침 3개 | 10,306 | 13,802 | 3,725 | 73.0% 감소 |
| 새 과업 기본 시작 — 빈 양식 포함 | 13,243 | 17,487 | 4,486 | 74.3% 감소 |
| 협업/연구 시작 — workflow 포함 | 17,547 | 22,848 | 6,555 | 71.3% 감소 |
| 과업 기록 템플릿 전체 | 7,512 | 9,533 | 761 | 92.0% 감소 |
| Wiki 기존 페이지 수정 준비 | 없음 | 11,958 | 2,485 | 79.2% 감소 |
| Wiki 새 페이지 준비 — 틀 포함 | 없음 | 13,170 | 2,959 | 77.5% 감소 |

기존 v2.1 과업의 빈 `brief.md + state.md`를 그대로 두고 새 지침만 적용하면 시작 분량은 **7,410자**다. 새 기록 양식에 따른 감소와 별도로 확인한 값이다.

문자는 ZIP의 UTF-8 텍스트를 Python `len(text)`로 계산한 코드 포인트 수다. 공백·줄바꿈·frontmatter·코드 블록을 포함한다. 실제 토큰·과금·시간이 아니다. 아래 항목을 서로 구분한다.

- 기본 시작: 이전은 README + principles + Astra + 빈 brief + 빈 state, v3 새 과업은 README + principles + Astra + 빈 task. 실제 내용이 채워지면 커진다.
- 지침만 비교: README + principles + Astra. 기록 형식 차이를 제외한다.
- 협업/연구 시작: 기본 시작 + 해당 버전 workflow. 고영향 과업을 짧은 경로에 숨기지 않는다.
- Wiki 기존 페이지 수정 준비: 이전 schema + playbook, v3 통합 playbook. 새 페이지는 각 버전 템플릿을 별도 추가한다.

과업 입력·원자료·도구 출력·런타임 추가 지시·캐시·검토 호출은 측정하지 않았다. 문서 분량 감소율을 비용 절감률이나 결과 품질 향상률로 해석하지 않는다. 원문과 참고 문서를 보관하는 것과 매번 모델에 전달하는 것은 다르다.

공식 형식은 2026-09-20에 GoogleCloudPlatform의 SPEC.md 공개 본문에서 0.2를 재확인했다. [요약과 범위](../wiki/sources/google-open-knowledge-format.md)에 출처를 남겼다. Karpathy 공개 최신 원문은 이번에 재조회하지 않았고 기존 사본의 바이트 보존만 확인했다.

**미검증:** 실제 다중 모델 실행, 사용자 WSL·프로젝트 적용, 장기 기록 성장, 동시 편집, 외부 OKF 소비 도구, 과금 토큰·시간·재작업 절감, 연구 결과 품질 보존. 배포된 시작 틀에는 실제 업무 실험값을 채우지 않았다.

## 8. 실운영 비교 — 미실행

v2.1과 v3를 같은 모델 배치·도구·권한·입력·성공 기준·내용이 동일한 Wiki 스냅샷으로 별도 세션에서 비교한다. 한 조건의 결과를 다음 조건 입력에 섞지 않는다. v1은 원자료 접근을 맞춘 참고 조건으로만 추가할 수 있다. 개별 구성 요소의 인과 효과는 별도 한 요소씩 바꾸는 실험이 필요하다.

대표 과제는 작은 수정, 근거를 재사용하는 실험 설계, Wiki 한 건 반영과 다음 질의다. 먼저 최종 성공 기준·실행 증거·누락을 확인하고 실제 읽기/쓰기/호출·재조사·사용자 개입·시간·제공되는 사용량을 기록한다. 지식 최초 구축 비용과 후속 재사용 이익을 함께 본다.

품질·근거가 떨어지면 분량이 줄어도 개선으로 판정하지 않는다. 소수 과제는 초기 문제 탐지용이지 최적성의 증명이 아니다. 필요한 경우 해당 규칙만 복원하고 모든 절차를 다시 의무화하지 않는다.
