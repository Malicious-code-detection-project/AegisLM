# Playbook · Architecture Review

조건: 신규 모듈/서비스, 공개 API, 신뢰 경계, 데이터 계약, 큰 변경 영향.

Sol: 문제·비목표·제약·현재 구조·제안 구조·대안·마이그레이션·rollback을 짧게 작성한다.
Luna: 실제 코드/호출/의존성의 증거를 제공한다.
Terra: 구현 난도, 테스트 가능성, 운영 비용을 검토한다.
Astra: 제안을 먼저 반증한다. 곧바로 더 큰 시스템으로 재설계하지 않는다.

검토 질문: 숨은 전제는 무엇인가? 실패가 어디까지 전파되는가?
계약이 어긋날 때 어떻게 탐지하는가? 취소·재시도는 멱등한가?
순서/일관성/권한/자원 한계를 어떻게 검증하는가? 더 작은 설계로 충분한가?

Sol은 대안과 finding 처리 근거를 [decision](../templates/decision.md)에 기록한다.
동의한 설계도 실제 구현의 검증을 대신하지 않는다.
