# Routing · role first, model second

## 먼저 결정할 것

Sol은 요구사항, 위험, 변경 범위, 검증 기준, 모델 접근 가능 여부를 먼저 확인한다.
단가만 보고 모델을 고르지 않는다. 역할 이름과 실제 모델 ID를 혼동하지 않는다.

| 의미상 역할 | 기본 모델 슬롯 | 소스 쓰기 | 필요 입력 |
|---|---|---|---|
| DIRECT / DIRECTOR / ARCHITECT / INTEGRATOR | Sol | 승인된 범위만 | 요구사항·계약·전체 영향 |
| SCOUT | Luna | 없음 | 조사 질문·경로·심볼 |
| BUILDER | Terra | WRITE SCOPE만 | 확정 계약·완료 조건 |
| VERIFIER | Luna | 없음 | 고정 후보·승인된 검증 명령 |
| REVIEWER | Terra의 **새 세션** | 없음 | 원 요구사항·diff·관련 코드·검증 |
| SPECIALIST | Astra | 기본 없음 | 좁힌 난제·현재 증거·실패 가설 |
| AUDITOR | Astra의 **독립 세션** | 없음 | 위협 모델·설계 또는 후보 diff·검증 |

Sol은 작은 작업을 직접 구현할 수 있다. Terra Builder가 자기 결과를 검토하는 것은 자체 점검이지 독립 리뷰가 아니다.
Astra가 설계를 직접 만든 경우 그 설계의 독립 심사자라고 기록하지 않는다. 새 검토 세션/다른 검토자를 확보한다.

## 위험 분류

| 위험 | 예 | 최소 수용 기준 |
|---|---|---|
| LOW | 좁은 내부 수정, 의미 변경 없는 문구, 독립 테스트 수정 | 의미 있는 검증 + Sol 최종 점검. 별도 리뷰는 필요에 따라 |
| MEDIUM | 다중 파일 동작 변경, 공유 유틸, 상태 처리, 추론/집계 로직 | Verifier + fresh Reviewer + Sol |
| HIGH | 인증/권한, 비신뢰 입력 parser, 보안 경계, 데이터 이관, 동시성, 공개 API 파괴, 배포 핵심 설정 | 위험별 검증 + 독립 리뷰 + Astra AUDITOR + Sol. 병합·배포 권한은 팀 정책대로 |

파일 개수만으로 위험을 낮추지 않는다. HIGH의 Astra가 독립 리뷰 범위까지 명시적으로 담당했다면
별도의 Terra 리뷰를 중복 수행하지 않아도 된다. 보안 리뷰만 했다면 기능적 정확성 리뷰는 별도로 남는다.
보안 프로젝트의 모든 문서 편집을 HIGH로 취급하지는 않는다. **변경이 보안·정확성 경계에 미치는 영향**으로 판단한다.

## 분기

1. 알려진 위치의 작고 명확한 변경이며 위임 이득이 없다 → Sol DIRECT.
2. 조사 질문이 분리된다 → Luna SCOUT.
3. 구현 계약과 WRITE SCOPE가 정해졌다 → Terra BUILDER.
4. 변경 완료 후 후보를 고정한다 → Luna VERIFIER, fresh Terra REVIEWER.
5. HIGH 또는 [승격 조건](escalation.md) → Astra. 심각한 설계 위험은 구현 전에 검토한다.
6. 증거 부족·검증 실패 → Sol이 추가 조사/재작업/전문 검토를 선택한다. 품질 기준을 낮추지 않는다.

## 병렬화

기본 최대 2개 하위 에이전트. 두 조사 작업, 또는 독립된 조사와 구현은 가능하다.
완료된 후보에 대한 Verifier와 Reviewer는 독립된 테스트 환경/불변 스냅샷에서 병렬 수행할 수 있다.
공유 테스트 DB, GPU, 포트, lockfile을 함께 건드리면 읽기 전용 소스 역할끼리도 충돌할 수 있다.
검증 중 후보 파일을 수정하지 않는다. 다른 writer가 있다면 잠금·소유권을 확인하고 멈춘다.
여러 writer는 서로 다른 worktree/브랜치, 비중첩 쓰기 범위, 통합 책임자를 확보한 경우에만 Sol이 추가 승인한다.
하위 에이전트는 다시 하위 에이전트를 생성하지 않는다.

## 컨텍스트

처음에는 해당 역할 문서, 적용 팀 규칙, 작은 task packet, 필요한 소스·테스트만 전달한다.
전체 대화·전체 references·전체 로그 전달은 기본 금지다. 로그는 위치와 요약을 전달한다.
필수 계약이나 반례가 빠졌다면 추가 파일을 읽는다. 작은 컨텍스트를 유지하려고 증거를 생략하지 않는다.

모델이 없을 때의 대체와 권한 문제는 [runtime](runtime.md), 품질 게이트는 [review](review.md)를 따른다.
